PHASE 3 / PERIPHERAL CONVENIENCE LAYER

STTiming v0.1.0-DEV

Detailed reference for non-blocking millisecond timing on the current Arduino Nano / ATmega328P checkpoint.

Purpose

Why it exists

delay() blocks the user loop. STTimer allows timed actions while the loop continues to execute other logic.

Execution model

No hidden scheduler. The application explicitly checks the timer from normal Arduino loop().

Timebase

The current implementation uses millis() and unsigned elapsed-time subtraction.

Basic use

#include <STTiming.h>

STTimer timer(1000);

void setup()
{
    timer.start();
}

void loop()
{
    if (timer.expired())
    {
        // action every interval
        timer.restart();
    }
}

API reference

FunctionMeaningStatus
start()Starts the timer from zero when stopped.PASS
elapsed()Returns elapsed milliseconds since the current start/restart.PASS
expired()True when elapsed time is greater than or equal to the interval.PASS
remaining()Returns milliseconds remaining, clamped to zero after expiry.PASS
reset()Clears elapsed time and stops the timer.PASS
restart()Clears elapsed time and immediately starts again.PASS
setInterval(ms)Changes the configured interval.PASS
interval()Returns the configured interval.PASS
running()Reports whether the timer is currently active.PASS

Semantics

reset()

timer.reset();

After reset: elapsed() = 0 and running() = false.

restart()

timer.restart();

After restart: elapsed() = 0 and running() = true.

Overflow-safe millis handling

The timer should compare elapsed time using unsigned subtraction:

elapsed = now - startTime;

This is safer than comparing against startTime + interval because normal unsigned wraparound is handled by modular arithmetic.

Hardware validation

Initial interval = 1000
Initial running = FALSE
After start(), running = TRUE
Elapsed before reset = 403
After reset(), running = FALSE
After reset(), elapsed = 0
After setInterval(2000), interval = 2000
After restart(), running = TRUE
--- 2000 ms TIMER EXPIRED ---
elapsed = 2000
remaining = 0
running = TRUE

Repeated 1000 ms restart cycles also produced consistent elapsed/remaining progression around 250/750, 500/500, 750/250 and expiry near 1000/0.

Important limitation

STTiming is non-blocking only if the rest of the sketch remains responsive. A long blocking call elsewhere in the loop can delay when expired() is checked. STTimer does not create a background scheduler.
