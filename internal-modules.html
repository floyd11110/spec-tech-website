MODULE ENGINEERING

Expansion & High-Speed Measurement

Core architecture

Invariant

PLC Logical Address != Module Address != Channel Address != Transport Address != Physical MCU Pin.

Purpose

PLC programs remain independent of bus technology, module electronics and MCU pin assignments.

Module Manager

Owns identity, configured address, capabilities, online state, diagnostics, scheduling and transport abstraction. Discovery is not configured/online state.

Data model

Use module family, channel, function, data and status instead of one PLC opcode per sensor model. D registers can be PLC-side interchange without dictating wire encoding.

Module families

ST-DI16

Protected 24 V digital input expansion, separate from built-in Mega X0-X15.

ST-DO16

24 V sinking transistor/MOSFET output expansion with explicit startup, fault and communication-loss behavior.

Analog / Sensor

ST-AI, ST-AO, ST-TEMP and sensor families use capability-driven interfaces and typed/scaled data.

ST-HSC / Precision Timing

Measurement authority

Capture physical edges locally using hardware timers/input capture, calculate in the module, then report to PLC. Communication latency after capture does not alter the measured interval.

Target functions

  • Continuous event count
  • Elapsed interval
  • Pulse width and period
  • Frequency and RPM
  • Event-to-event timing

Why dedicated hardware?

Mega scan can represent millisecond values but cannot honestly guarantee +/-1 ms physical edge measurement. Dedicated capture removes normal scan timing from measurement authority.

Communication rules

  • Physical bus is not frozen; do not bind PLC semantics to RS485, CAN, I2C or SPI.
  • Reserve system/broadcast/unassigned addresses and detect duplicates deterministically.
  • Polling must be asynchronous/non-blocking relative to PLC scan.
  • Expose stale/timeout/fault diagnostics instead of silently reusing old data.
