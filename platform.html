Resource ownership

STM32F103C8 resource map

Resource ownership is explicit so reusable libraries do not silently fight over the same STM32 peripheral.

ResourcePrimary owner / useImportant rule
PA8 / TIM1_CH1Basic PWM, test signal sourceOne active owner at a time.
PA6 / TIM3Capture / SignalAnalyzer CapturePA6 is also SPI1 MISO; do not share it while Capture is active.
PA0 / TIM2Counter / SignalAnalyzer CounterConflicts with Basic TIM2 ownership and PA0 ADC while Counter is active.
PB6 / PB7I2C1 shared busDevice libraries share the SPEC-TECH I2C layer; unique addresses are required.
PA9 / PA10USART1 debug / FTDICommon debug and serial validation path.
PA13 / PA14SWDReserved for programming/debugging.

Release engineering

How a SPEC-TECH library becomes a retained release.

01

Design

Define purpose, API, pins, peripherals, dependencies, and conflicts before coding.

02

TEST / Development

Develop the feature set without modifying an existing frozen known-good release.

03

Hardware Regression

Run real-board tests, edge cases, restart/recovery checks, and resource-cleanup tests.

04

Installed / Soak Gate

Repeat regression from the packaged library and run soak testing where appropriate.

05

STABLE / FINAL / FROZEN

Retain the known-good version. Future behavior changes branch to a new version.

Current STM32 development direction

Dual-signal timing foundation

The next planned timing work is a new TEST branch for synchronized two-signal timing, intended to support future phase, propagation-delay, edge-order, and dead-time analysis without modifying the frozen Capture or SignalAnalyzer releases.
