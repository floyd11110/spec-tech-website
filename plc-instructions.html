Agreed architecture

Next data-oriented functions

These behaviors have been defined conceptually but are not being represented as implemented until firmware, Studio, readback, online edit, monitoring, and hardware tests are complete.

AGREEDContinuous Timer

No preset; non-retentive elapsed time

Accumulates elapsed time continuously while its rung/input is TRUE. There is no PRE or DONE threshold. When the input becomes FALSE, the accumulated time returns to zero. Its numerical elapsed value is intended to be transferable/readable through the data-register system.

No PRETRUE = AccumulateFALSE = ZeroData Source
AGREEDContinuous Counter

No preset; retentive pulse/event count

Increments once per valid rising-edge pulse, retains the accumulated count when the count input is FALSE, and returns to zero only when its dedicated reset function is energized. Intended for product, piece, package, cycle, reject, and general event counting.

Spec-Tech extensions

ST module function-block architecture

The long-term goal is to keep low-level bus timing, sensor protocols, conversion, status handling, and module-specific implementation out of ordinary ladder logic. ST function blocks expose useful machine data and commands through a consistent PLC interface.

Architecture principle

Standard PLC logic + Spec-Tech hardware-aware functions

Simple operations remain ordinary instructions. Stateful or hardware-specific behavior can be represented as function blocks. The D-register/data layer is intended to become the common numerical interface between ladder logic, timers/counters, analog processing, HMI/logging, communications, and ST modules.
