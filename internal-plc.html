PLC scan & timing technique

Principle

PLC execution is cyclic. Physical input edges are observed through the scan, so event response contains scan-dependent uncertainty.

Timer design

Elapsed time should derive from timebase difference rather than one increment per scan, avoiding cumulative scan-count drift.

Limitation

A millisecond numeric value does not prove +/-1 ms physical input-to-output accuracy. Precision edge timing belongs in dedicated hardware-timed acquisition.

Compiler & Online Edit

Compiler

Studio converts graphical ladder topology into the PLC instruction stream. PUSH/ORS support grouped parallel paths.

Structural Online Edit

Edits can change instruction count. Staged changes apply at scan boundary while preserving validated runtime R/M/T/C state and then commit to EEPROM.

Recovery journal

Journaled Online Edit has controlled fault-injection power-loss recovery validation at the tested interruption point; this is not exhaustive arbitrary-time certification.

Reliability rules

  • Never block PLC scan indefinitely on module/network transactions.
  • Keep PLC logical addressing independent from transport and physical pins.
  • Record firmware/Studio compatibility for retained checkpoints.
  • Hardware PASS only after physical confirmation.
  • Future external data should expose GOOD/BAD/STALE/DISCONNECTED/TIMEOUT quality.
