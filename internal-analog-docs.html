ST EMBEDDED DOCUMENTATION

STAnalogIO v0.2.0-DEV

Detailed reference for analog input sampling, averaging, voltage conversion, configurable ADC reference voltage, and PWM output on the current Arduino Nano / ATmega328P checkpoint.

1. What STAnalogIO is

Purpose

STAnalogIO wraps common Arduino analog operations in lightweight objects. STAnalogInput handles ADC sampling and conversion. STAnalogOutput handles PWM output through Arduino analogWrite().

Execution model

All reads and writes happen only when called by the user sketch. There is no hidden sampler, scheduler, interrupt service, heap allocation, or required ST.run().

Current validation target

Arduino Nano / ATmega328P @ 16 MHz using the current ST Embedded IDE checkpoint.

2. STAnalogInput — creating an input

#include <STAnalogIO.h>

STAnalogInput sensor(A0, 5.0f);

A0 is the analog pin. 5.0f is the voltage reference value used by the library when converting ADC counts to volts.

Reference voltage is a conversion assumption

Passing 5.0f does not measure the Nano supply. If the real reference is 4.90 V, use 4.90 V for better conversion accuracy. Raw ADC operation can be correct even when absolute voltage accuracy is limited by an inaccurate reference assumption.

3. begin()

Initializes the analog input object for use. The current API keeps setup explicit and consistent with the rest of the ST convenience layer.

void setup()
{
    sensor.begin();
}

4. read() — one raw ADC sample

read() performs one ADC conversion and returns the raw Nano ADC count.

int raw = sensor.read();

Serial.println(raw);

On the validated classic Nano target, the observed range was:

Input conditionObserved ADC
Near GND0
Intermediate potentiometer positionsValues throughout the range
Near reference/full scale1023

5. readAverage(samples) — averaged ADC reading

This function takes multiple ADC samples and returns their arithmetic average. It is useful when a sensor has small random sample-to-sample variation.

uint16_t average = sensor.readAverage(10);

Conceptually:

sample1 + sample2 + ... + sampleN
-------------------------------- = average
                N

Example from the hardware test:

RAW = 457 | AVG10 = 458
RAW = 485 | AVG10 = 486
RAW = 649 | AVG10 = 649
RAW = 866 | AVG10 = 865
What averaging does

It smooths small random variation. It does not magically correct calibration error, bad grounding, clipping, sensor drift, or a wrong voltage reference.

6. readVoltage()

Reads the ADC and converts the count to volts using the configured reference voltage.

For the current Nano implementation, the conversion corresponds to:

Voltage = ADC × Vref / 1023

Example: with Vref = 5.0 V and an ADC reading around 485, the measured output was about 2.375–2.380 V.

float volts = sensor.readVoltage();

7. readAverageVoltage(samples)

This combines multi-sample averaging with voltage conversion.

float avgVolts = sensor.readAverageVoltage(10);

Hardware validation reached both endpoints:

RAW = 0    | AVG10 = 0    | V = 0.000 | AVG V = 0.000
RAW = 1023 | AVG10 = 1023 | V = 5.000 | AVG V = 5.000

8. Why raw, average, voltage, and average-voltage can differ slightly

If the sketch calls these functions one after another, they are not all based on one identical ADC sample.

sensor.read();                  // one sample
sensor.readAverage(10);         // ten new samples
sensor.readVoltage();           // another new sample
sensor.readAverageVoltage(10);  // ten more new samples

If a potentiometer or sensor is moving, small differences are expected because each call observes the signal at a different time.

9. Reference voltage configuration

referenceVoltage()

Returns the reference voltage value currently stored by the object.

Serial.println(sensor.referenceVoltage(), 3);

setReferenceVoltage(volts)

Changes the conversion reference used by future voltage calculations.

sensor.setReferenceVoltage(4.900f);

Validated behavior

PIN = 14
INITIAL VREF = 5.000
NEW VREF = 4.900
ADC = 1023
VOLTAGE USING 4.900 VREF = 4.900

This confirms that the conversion tracks the configured reference value.

10. pin()

Returns the configured Arduino analog pin value. On the validated Nano target, A0 reported numerically as 14.

Serial.println(sensor.pin());  // observed: 14

11. STAnalogOutput — PWM output

STAnalogOutput pwm(9);

void setup()
{
    pwm.begin();
}

The current implementation wraps Arduino PWM output. On the Nano test, D9 was used.

PWM is not a true DAC voltage

analogWrite() on the classic Nano produces a digital PWM waveform on supported PWM pins. A value such as 128 means approximately 50% duty cycle, not a steady analog voltage of half the supply unless external filtering/load behavior makes it appear that way.

14. Basic PWM example

#include <STAnalogIO.h>

STAnalogOutput pwm(9);

void setup()
{
    Serial.begin(115200);
    pwm.begin();
}

void loop()
{
    pwm.write(0);
    delay(1000);

    pwm.write(64);
    delay(1000);

    pwm.write(128);
    delay(1000);

    pwm.write(192);
    delay(1000);

    pwm.full();
    delay(1000);

    pwm.off();
    delay(1000);
}

15. Complete analog input example

#include <STAnalogIO.h>

STAnalogInput sensor(A0, 5.0f);

void setup()
{
    Serial.begin(115200);
    sensor.begin();
}

void loop()
{
    int raw = sensor.read();
    uint16_t avg = sensor.readAverage(10);
    float volts = sensor.readVoltage();
    float avgVolts = sensor.readAverageVoltage(10);

    Serial.print("RAW = ");
    Serial.print(raw);
    Serial.print(" | AVG10 = ");
    Serial.print(avg);
    Serial.print(" | V = ");
    Serial.print(volts, 3);
    Serial.print(" | AVG V = ");
    Serial.println(avgVolts, 3);

    delay(500);
}

17. Common mistakes

MistakeProblemCorrection
Treating 5.0f as measured VccAbsolute voltage can be inaccurateMeasure the real reference when accuracy matters
Expecting average to fix calibrationAveraging only reduces random variationCalibrate reference/sensor separately
Expecting every API call to use one sampleEach read function can acquire new ADC samplesStore one raw value if a single snapshot is required
Calling PWM a true analog voltageNano analogWrite is PWMDescribe it as duty-cycle output unless externally filtered
Using a non-PWM pin for variable PWM outputHardware capability differs by pinUse a supported PWM pin such as the validated D9 checkpoint
